# Academic Assistant Web · Study OS v0.1

Academic Assistant 的桌面学业工作台，沿用 React 19、TypeScript、Vite 与现有组件，不增加运行依赖。暖米色、钴蓝色、细描边和本地 Lyusung 像素字体构成统一的 Study OS 风格；中文长文本使用系统无衬线字体。

## 首页工作台（本地演示）

```bash
cd client/web-client
npm ci
npm run dev
```

直接打开 **http://localhost:5173/?demo=1**，无需后端、账号或环境变量。也可以从登录页点击「先体验工作台」。带 `?demo=1` 的预览不会请求任何 API，不读写真实账号、课程或 Agent。

- **主页与对话共用一个工作台**：左侧显示问候、学业统计、今日时间线、学业简报、课程进度和任务；右侧常驻学习助手。顶部「对话」只聚焦右侧输入框。
- **独立滚动**：桌面左右分别滚动，输入框固定在右栏底部。窄屏改为纵向排列。
- **本地聊天**：建议问题可直接发送；支持发送按钮、Enter 发送、Shift + Enter 换行、中文输入法、等待状态和新对话。按问题关键词返回本地回复，无模型调用。
- **课程与任务**：展开全部五门课程、查看课程与任务详情、从任务发起对话。
- **日程 / 我的**：独立的简单页面，支持示例日期切换和本次浏览的提醒开关。切换导航保留聊天内容。
- **示例边界**：所有学业示例、课程、时间线、建议问题和回复统一存于 `src/data/mock.ts`；示例日期为 2026-11-12，页面时钟与问候使用当前北京时间。聊天与偏好仅存在当前组件会话，刷新后重置。

登录、引导页已同步重绘。原有登录、授权和导入流程继续使用既有 API，完成设置后可进入工作台；已完成设置的用户再次登录时直接进入工作台，「我的 → 查看设置」可返回向导。**工作台中的学业数据仍全部是示例，不展示或同步真实平台数据。**

## 登录与引导（沿用原有后端）

需要 Node.js 22.12+，默认后端为 `http://127.0.0.1:2610`。

```bash
cd client/web-client
npm ci
npm run dev
```

访问 `http://localhost:5173`，使用管理员创建的 HAA 账号登录。没有内置账号、自助注册或默认密码。学校统一认证账号在向导第二步连接。

如后端在其他地址，复制 `.env.example` 为 `.env.local` 后设置 `HAA_API_TARGET`。Vite 将 `/api` 与 `/admin` 代理至后端。开发代理先校验写请求的浏览器 Origin 与网页 Host 一致，拒绝缺失或跨源的请求，再将上游 Host/Origin 转换为后端地址；后端仍负责 Session 和 CSRF 校验。若后端 `PUBLIC_ORIGIN` 与 `HAA_API_TARGET` 的 Origin 不同，设置 `HAA_BACKEND_ORIGIN` 与它一致，无需修改或重启后端。localhost 与 127.0.0.1 的浏览器会话不互通，请固定使用一个访问地址。

本工作区的 2610 端口目前用于临时批次处理服务，未挂载完整平台与日程接口。网页通过 `.env.local` 连接完整 API 实例 `http://127.0.0.1:2611`。该实例使用后端 `API_ONLY=true` 模式，共用已有数据库与密钥，保留授权与手动操作，不启动全局采集或 Agent 批次执行。重新启动时，可在加载后端配置后运行 `API_ONLY=true HTTP_ADDR=127.0.0.1:2611 PUBLIC_ORIGIN=http://127.0.0.1:2611 go run ./cmd/api`。

不要仅用 `/health` 判断后端是否支持网页。完整服务在未登录时应对 `/platforms/sources`、`/platforms/connections`、`/dws/connections`、`/schedules` 返回 401；若返回 404，说明当前地址没有挂载这些接口。

## 已实现流程

1. **登录**：恢复已有会话、密码显隐、登录错误、退出和会话过期处理。普通用户不显示管理后台入口。
2. **连接学习平台**：钉钉 DWS、学习通、中国大学 MOOC、U 校园。扫码状态轮询、过期重试、网络中断后继续检查；具体可用能力由 `/platforms/sources` 决定。
3. **钉钉采集范围**：分页发现群、搜索已加载群、选择最多 100 个群。群列表加载失败不会清空已有授权；无法读取原配置时禁止保存。绑定钉钉不代表自动读取全部群。
4. **连接杭电教务**：使用统一身份认证账号登录，请求完成后清空密码，不把密码写入浏览器存储。
5. **设置学期**：学年、学期、第一教学周周一；校验周一和学年范围。
6. **设置作息与导入**：生成和逐节编辑时间、添加、删除、顺延，校验节次、起止时间及重叠。连接教务后提交完整 calendar 手动导入课表，显示后端真实返回的导入统计；导入失败保留设置供重试。

学习平台和教务均可稍后连接。未连接教务时完成向导仅保存设置，不声称课表已经导入。

## 数据保存与范围

- 平台连接、钉钉群范围和已导入日程由既有后端持久化、按用户隔离。
- 后端当前没有学期/校历偏好接口。向导进度、学年学期和节次作息使用 `haa:setup:v1:<user_id>` 保存在当前浏览器。换浏览器或清除网站数据需重新设置；不会跨设备同步。课表导入时会将这些配置传给后端生成实际日程。
- 不保存学校密码、授权二维码、Cookie 或 Token 到 localStorage；应用 Session 使用后端 HttpOnly Cookie，写请求提交 `X-CSRF-Token`。
- 向导完成页提供设置概览、重新设置与进入工作台入口；工作台与本地 AI 对话使用独立 Mock Data，不接入真实平台采集结果。
- 后端增加 `API_ONLY` 运行选项，用于完整 HTTP 接口与既有后台任务分开运行；没有增加数据库迁移或修改账号数据。

## 构建与验收

```bash
npm run build
npx playwright install chromium
npm test
```

可设置 `CHROMIUM_PATH=/path/to/chrome npm test` 使用已有 Chromium。工作台测试直接使用零 API 请求的本地预览；原有流程测试通过浏览器拦截 API 返回合成数据，覆盖登录与角色入口、扫码和异常恢复、DWS 群分页与保留配置、教务及课表请求、时间校验、失败重试、草稿隔离和手机布局。测试不会访问真实学校账号或发起真实课表采集；Mock 通过不代表上游平台实测通过。

```bash
npm run format
```

图标来自 `lucide-react`，授权 URI 二维码由 `qrcode` 在本地生成。像素字体使用已提供的 `fonts/lyusung-24px-square.woff2`，由 Vite 打包为本地资源；像素电脑与山景为 SVG。没有外部字体、图片或二维码生成服务依赖。

## 部署

`npm run build` 生成 `dist/`。静态文件与 `/api` 反向代理应部署在同一 Origin；`/admin` 可继续代理到原后端管理页。生产环境 HTTPS 下，后端需设置相符的 `PUBLIC_ORIGIN` 与 `COOKIE_SECURE=true`。`npm run preview` 仅用于本地检查构建产物。
